# Phase 3 設計: ブロックエディタ(Markdown 互換)

状態: 設計確定(2026-10-02、オーナーの判断を「6. 決定」に記録)。実装は未着手。

結論: Phase 3 の新規実装は、実質 **(1) ブロックのドラッグハンドルと並べ替え、(2) 折りたたみの目印、(3) スラッシュメニューの項目追加と見た目** の 3 つ。コールアウト、チェックボックス、折りたたみの仕組みは既存を使う。

## 2. 設計判断(私の推奨。未決は 6)

1. **保存形式は通常の Markdown のまま。** ブロック ID は付けない(`^id` は必要な箇所だけ、という計画のとおり。今回は不要)。
2. **ブロックの定義は、構文木のトップレベルとリスト項目から導く。** 新しいデータ構造は持たず、`syntaxTree` から純関数 `blocksOf(state)` で得る。単位は次のとおり。
   - 段落、見出し、引用(admonition を含む)、コードブロック、表、水平線、フロントマター以外のウィジェット行
   - リスト項目: **その項目と、入れ子の子を丸ごと**を 1 ブロックにする
   - フロントマターは対象外
3. **ドラッグハンドルは、各ブロックの 1 行目の左端に出す。** ホバー(またはブロックにカーソルがあるとき)に表示し、タッチ端末では出さない(ツリーのハンドルと同じ見た目・同じ流儀)。ハンドルをつかんで、他のブロックの前後へ落とすと並べ替わる。
4. **移動は、1 回のトランザクションで「元を削除して、先に挿入」する。** CodeMirror の undo(`Ctrl-z`)でそのまま戻せる。専用の Undo コマンドは作らない(Phase 2 のツリーと違い、エディタには標準の履歴がある)。
5. **インデント(階層)は、ドロップ位置の縦と横で決める**(決定 D)。リスト項目を別の項目の間に落とすとき、横方向の位置で階層を選ぶ(下記 2a)。階層の変更は、従来どおり `Tab` / `Shift-Tab` でもできる。
6. **折りたたみの目印は、ガターではなく行内のトグル(`▸`/`▾`)にする。** 見出しとリスト項目の左(ハンドルの隣)に出し、クリックで既存の fold を切り替える。折りたたみの状態は**保存しない**(ページを開き直すと開いた状態)。Markdown を変えないため。
7. **スラッシュメニューは、既存の仕組みに項目を足す。** 箇条書き、番号リスト、引用、画像、ページリンク、日付を追加。Space Lua のライブラリ(`Slash Commands/`)に定義するので Rust は不要。見た目(アイコン・説明)は、既存の `slashCommand.define` のフィールドの範囲で整える。

### 2a. ネスト変更(リスト項目のドロップ)
- 対象は**リスト項目だけ**。段落・見出し・表・コードなど、リスト以外のブロックは階層を持たない(トップレベルのまま、リストの途中には落とせない。リストの前後には落とせる)。
- 項目 X(深さ d)と項目 Y(深さ e)の間に落とすとき、入れてよい深さ k は **e ≤ k ≤ d+1**(Markdown では 1 段ずつしか深くできないため。k が e より浅いと Y が子になって構造が変わるので許さない)。X が無い(リストの先頭)なら k = 0、Y が無い(末尾)なら 0 ≤ k ≤ d+1。
- 横方向の位置 → 深さ: ポインタの x を、リストの基準位置からのインデント幅(px)で割った値を丸め、[e, d+1] に収める。許される深さの候補は、挿入ラインの左端の位置で見せる(1 本の線が、深さごとに左へ右へ動く)。
- 移動する項目の子は、深さの差(k − 元の深さ)だけ、**インデント幅ごと**ずらして付いていく。インデント幅は、そのリストの既存の字下げ(スペース 2/4 個、またはタブ)から読み取る。
- 番号リストは、移動後に番号を振り直さない(Markdown は表示時に番号を振るため、先頭の番号以外は意味を持たない)。

## 3. UI 設計ルールへの落とし込み

エディタは CodeMirror の上に載るので、ルールの各語を次のように当てはめる。

- **Root 階層:** `EditorView`(Root)→ ブロックハンドルの層(`ViewPlugin`)→ 各ブロックのハンドル / トグル(`WidgetType`)→ ドロップ位置の挿入ライン。
- **Passive View:** ハンドル・トグル・挿入ラインは、「ブロックの一覧」と「いまの状態」を受け取って描くだけ。位置の計算、移動の可否の判断、本文の変更は一切しない。
- **Chain of Responsibility:** ハンドルの `pointerdown` / `dragstart` / `dragover` / `drop`、トグルの `click` は、イベントとして上へ投げる(`emit`)。途中の層は自分が扱えるものだけ処理し、残りを親へ渡す。
- **Mediator(状態機械):** 純関数 `transition(state, event) → {state, effects}`。
  - 状態: `idle` / `hovering(block)` / `dragging(block, target)` / `committing`。
  - 効果: `move(block, placement)`(トランザクションを 1 つ dispatch)、`toggleFold(block)`、`notify`。
  - 実行は runner が行い、`EditorView.dispatch` は runner だけが呼ぶ。
  - `transition` と `blocksOf` と移動の計算(`planBlockMove`)は純関数で、DOM も CodeMirror も無しにテストできる。

## 4. 実装の順序

1. **`blocksOf` と `planBlockMove`(純関数 + テスト):** ブロックの範囲の導出と、移動後のテキスト(リストのインデント調整を含む)の計算。テキスト入力と期待出力の表でテスト。
2. **Mediator と runner(純関数 + テスト)。**
3. **CodeMirror への接続:** ハンドルと挿入ライン。`buildPageExtensions`(`client/codemirror/editor_state.ts`)の拡張配列に 1 つ足すだけ(既存ファイルの変更は最小)。
4. **折りたたみの目印。**
5. **スラッシュメニューの項目追加。**
6. **`Help: Fork Guide` の更新、E2E(実ブラウザ)での確認。**

## 5. 検証計画
- 単体: `blocksOf`(段落・見出し・入れ子のリスト・引用・表・コード・フロントマター・空行の扱い)、`planBlockMove`(前後への移動、入れ子の項目、同位置のドロップが無変更になること、自分の中へのドロップを拒否)、`transition`(状態 × イベント)。
- 実ブラウザ(Playwright): ドラッグで並べ替え、`Ctrl-z` で元に戻る、リストの子ごと動く、見出しの節ごと動く(6 の判断次第)、折りたたみのトグル、スラッシュメニューの新項目。コピーのスペースだけで行い、`/srv/*` には触れない。

## 6. 決定(オーナー判断、2026-10-02)
- **A. 見出しのハンドルは節ごと動かす。** 見出しと、次の同位以上の見出しまでの本文を一緒に移動する(Markdown の構造と、検索サイドカーの `##` ごとの節に一致)。
- **B. 折りたたみの状態は保存しない。** ページを開き直すと全部開いた状態。Markdown もブラウザの保存も変えない。
- **C. 範囲は全部**(並べ替え、折りたたみの目印、スラッシュ項目の追加)。
- **D. 横方向のネスト変更を v1 に含める**(上の 2a)。

## 7. リスク
- CodeMirror の `WidgetType` を行頭に置くと、カーソル移動やクリック位置の計算に影響しうる(`clean.ts` などの既存の装飾との相性)。ハンドルは行の外側(`position: absolute` でコンテンツ幅の外)に置き、既存の `Decoration.line` の仕組みに合わせて干渉を避ける。
- ネスト変更のインデント幅の判定: タブとスペースの混在、1 段が 2 個か 4 個か揺れるリストでは、読み取りを誤りうる。最初の入れ子の字下げを基準にし、判定できないときは 2 スペースを既定にする。
- 日本語・IME 入力中のブロック再計算(組み立て中の文字列でブロックの範囲が揺れる)。入力中はハンドルの再計算を遅延させる。
- 大きなページでの `blocksOf` の再計算コスト。変更のあった範囲だけ更新する(`ViewPlugin` の `update` で `docChanged` と可視範囲に限定)。
