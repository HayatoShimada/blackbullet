# BlackBullet のデザイン(日本語の要約)

英語の原本: [`product-design.md`](product-design.md)(意味の層: 概念・仕事・画面・一貫性の規則)と [`design-system.md`](design-system.md)(形の層: トークン・部品・動き)。判断の根拠や細部は原本を参照してください。この文書は要約であり、原本と食い違う場合は原本が正です。

指針の一文: **BlackBullet は、自分が所有する Markdown ファイルとしてのノートであり、素早く捕まえ、安く整理し、意味で見つけ、質問できるエディタである。AI は受信箱の鍵を持つ客であって、家の主ではない。**

## 1. 概念と語彙(1 概念 1 名称)
ラベル・コマンド・ガイド・空の状態・エラー文は、この語彙だけを使います。UI(クローム)は英語、ガイドは日本語で、同じ概念を 1:1 で対応させます。

| 概念 | ユーザーにとって | 見せ方 | 見せないもの |
| --- | --- | --- | --- |
| ページ Page | Markdown ファイル 1 つ。すべての単位 | 名前 = パスの末尾、フォルダは薄いパンくず「Projects ›」 | `.md`、「オブジェクト」 |
| フォルダ Folder | ページをまとめるパスの前半。移動するとリンクが追従 | ツリーのノード、パンくず | 「ディレクトリ」 |
| タグ Tag | ページやタスクの `#語` | チップ | `tags:` キー |
| データベース Database | プロパティを共有する、宣言されたページの集合。1 つのフォルダとテンプレートを持つ | 題名と「+ New」 | 「タグ + frontmatter + フォルダ」、`database.define`、YAML |
| プロパティ Property | 行の型付き項目(選択・日付・ページ・数・文字) | 列見出し、チップ、セルの編集 | 「属性」「frontmatter のキー」 |
| 行 Row | データベースに属する 1 ページ | 表の行、ボードのカード、カレンダーのカード | 「レコード」 |
| ビュー View | データベースかタスクを見るレンズ。Table · Board · Calendar。`db` ブロック = ビュー。「Save view」でタブ・並び・絞り込みをブロックに書き戻す | タブ、Save view | 「ウィジェット」「iframe」、英語 UI 内の日本語ラベル |
| タスク Task | どこにでも書けるチェック行。Done と Due を持つ | チェック + 文 + Due + Page | `@195` のような位置 |
| ジャーナル Journal | 1 日 1 ページ。「Today」が入口 | Journal: Today、前後の日 | ヘッダのフォルダパス |
| クイックノート / 受信箱 Quick note / Inbox | 数秒で捕まえる動作と、その置き場 | 「Quick note · 11:17」 | `Inbox/2026-10-02/11-17-18` という題名 |
| テンプレート Template | New が複製する `Templates/` のページ | New で名前を選ぶ | `${title}` の仕組み |
| 検索 Search | 語と意味の両方で節を探す 1 つのモーダル | Search(`Ctrl-q s`) | 「Memo」「サイドカー」「スコア」 |
| 関連ノート Related | 開いているページに近いページ(意味 / リンク) | Related notes パネル、チップ Similar / Linked | 数値 |
| グラフ Graph | ページがノード、リンク・言及・類似が辺 | Graph(`Ctrl-Shift-g`) | 「Object Graph」「セマンティック」 |
| 質問 Ask | ノートから `[1]` の引用付きで答える。保存は `Ask/` | Ask(`Ctrl-q a`) | 「Memo: Ask」、モデルの設定 |
| 文書 Document | PDF などの Markdown でないファイル。検索でき、開けるが編集しない | ファイルのアイコン、`PDF p.3` | 「添付」 |
| ゴミ箱 Trash | UI からの削除はすべて `Trash/` へ。完全削除はゴミ箱の中だけ | Move to trash、Trash: Restore、Trash: Empty | 一発の「Delete」、`trashedFrom` |
| ホーム Home | `index` ページ | Home | 題名としての「index」 |
| パネル Panel | ドックに入るクロームの面(ツリー、関連ノート、Ask、検索) | 題名 | `view.define`、「dock」 |

ユーザーが知らなくてよいこと: データベースの内部表現、検索・関連・グラフ・Ask が同じサイドカーを使っていること(設定は 1 つ、停止時のメッセージも 1 つ「Search by meaning is off」)、スコアや埋め込み、ビューが iframe であること、`@位置` の参照。

フォルダの契約: `Home`(index)· `Inbox/`(クイックノート、MCP の `add_inbox`)· `Journal/` · `Projects/` `Areas/` `Goals/` `Resources/`(データベースか普通のフォルダ)· `Templates/` · `Ask/`(保存した回答)· `Trash/` · `Library/`(ユーザーが編集しないコード。ピッカーとタスク一覧から隠す)· `CONFIG`(設定。ピッカーから隠す)。

## 2. 仕事と主要な流れ
| 仕事 | 1 操作で届くもの | 流れと決め事 |
| --- | --- | --- |
| 捕まえる | `Ctrl-q q` クイックノート、`Ctrl-q j` 今日のジャーナル。スマホは + New → Quick note | 開いた瞬間にカーソルがあり、プレースホルダ「Write it down. It is saved as you type. Esc goes back.」。Esc で元のページへ |
| 整理する | `Ctrl-o` ツリー、ドラッグで移動、`Ctrl-k` → `Shift-Enter` でそのフォルダに作成 | **New は 1 つ**(`Ctrl-Alt-n`、ツリーの +、パレット): Page here · Row in <database>… · Quick note · Journal: Today の順をどこでも同じに。段階的に Database: New Database、Pin、Move to…、Rename、Archive |
| 見つける | `Ctrl-k` 名前で開く、`Ctrl-q s` 検索、`Ctrl-Shift-g` グラフ | 検索モーダルは 入力 → 件数 → 結果(Page › Section + 一致した文)→ ヒント。`in:` `kind:` `#` の範囲指定は段階的に。グラフは今のページと隣接ノードから始める。サイドカーが無いときは赤い帯ではなく「何が止まっていて次に何をするか」 |
| 計画する | Tasks ページ、ホームの Due soon | チェックは消えるのではなく打ち消し線 + 「Done · Undo」(8 秒)。期限は ISO 日付 + 「overdue」などの語。タスクのボードはページ単位、データベースのボードは最初の選択プロパティ |
| 振り返る | `Ctrl-q j` 今日、`Ctrl-q p / n` 前後の日 | ジャーナルは日付が題名。`@today` でリンク |
| 尋ねる | `Ctrl-q a` | 1 つの入力 → `[1]` 引用付きの回答 → Follow-up · Save answer · New conversation。鍵が無ければ説明と「Set up Ask」 |
| AI から使う | 画面には何も無い | 契約はフォルダ構成: AI は Inbox と Journal に書き、CONFIG と Library 以外を読む。`./setup.sh` が MCP の接続コマンドを表示 |

## 3. 画面ごとの要素の優先順
- ホーム: ①捕まえる行(Quick note · Today's journal · Search)②Due soon ③Active projects(表、5 行)④直近 7 日のジャーナル ⑤最近編集。内容があれば「Welcome…」は出さない
- ページ: ①題名 + パンくず(カバーとアイコンがあれば)②プロパティのチップ ③本文 ④関連ノート(折りたたみ)⑤被リンク。ブロックの取っ手と折りたたみはホバー時のみ
- ビュー: ヘッダ 1 行 `Projects · 6` · Table | Board | Calendar · Filter · + New · ⋯。表は Name が先頭で固定、宣言順のプロパティ、Page は最後、行の `⋯` は末尾
- 検索モーダル、Ask パネル、グラフ、コマンドパレット(入力 → 最近 5 件 → おすすめ → 接頭辞ごと。危険・開発者向けは入力したときだけ)、ツリー(名前が最優先、操作はホバーか `⋯`)、ページピッカー(Library/Templates/Trash/CONFIG は隠す)

## 4. 一貫性の規則(検証できる形)
1. New は 1 つ、同じ順で
2. Filter は 1 つ(その場の一覧を絞る)。Search を Filter と呼ばない
3. 同じ動作には同じ見た目: 行のメニューは `⋯` のポップオーバー(Esc とクリック外で閉じる、最初の項目にフォーカス、危険な項目は最後で赤)。セルの編集はホバーで鉛筆、タッチは 1 タップ、Enter で保存、Esc で取消。ドラッグは `⠿`、タッチは長押し、落とす位置に線、Esc で取消
4. 通知は 2 文まで(何が起きたか、次に何をするか)。コマンド名の接頭辞なし。帯は本文に重ねない
5. 可逆が既定: チェック・ゴミ箱・移動・アーカイブ・並べ替えは「<動詞> · Undo」8 秒。完全削除はゴミ箱の中だけで、確認する
6. ダイアログ: 対象名を含む問い + 結果 + Cancel に初期フォーカス + 動詞のボタン、危険な動詞は赤
7. 日付は ISO、必要なら overdue / today / tomorrow の語。完了した行に赤い日付を出さない
8. 英語の UI、日本語のガイド。混在させない
9. ショートカット体系: `Ctrl-文字` = 編集(上流どおり)/ `Ctrl-Shift-文字` = 画面を開く / `Ctrl-q 文字` = クイック(q ノート、j ジャーナル、p/n 日、t テンプレート、s 検索、a Ask、r 関連)/ `Ctrl-Alt-文字` = 道具(n New)。Esc は常に「離れる」、その後の Tab でエディタから抜ける
10. タッチ: 親指が必要な操作部は 44px 以上。入力は 16px。ホバーだけの操作には必ずタップの代替
11. 読み込みと失敗: 節ごとのスケルトン、ページ全体のスピナーは無し。想定内の「無い」はエラーとして記録しない
12. Markdown が正: クロームの操作はすべて手で書けるファイル変更に対応し、拒否するときは理由を言う(読んだ後にページが変わった)
13. AI は客: Ask を実行しない限り何も外に出ない。サイドカーの停止はメッセージに退化し、壊れた画面にはしない

## 5. 空の状態と初回(次の一歩を教える)
ホームの各節、空のデータベースビュー、サイドカーの無い検索、鍵の無い Ask のそれぞれに、状況と次の操作(ボタン)を 1〜2 文で。

## 6. 削除・統合したもの(抜粋)
ビュー上部の二重のコピーボタン、タッチ時に常時出るホストバー、検索の Compact/Details、関連ノートの数値、「Memo:」接頭辞、「Object Graph」「Semantic edges」の語、ツリーの選択行に常時出る 4 つのアイコン、「Bookmark」(→ Pin)、一発の「Delete」(→ Move to trash)、ビュー内の日本語ラベル、空のパレット一覧に出る Client: Wipe などの危険・開発者向けコマンド、ピッカーに出る Library/CONFIG/Templates/Trash、`Page@96` の参照、生のパスの題名、`mm/dd/yyyy`、既定の等幅書体。

## 7. 形の層(design-system.md の主な決定)
- **書体**: 本文と UI は OS 標準の proportional(ui-sans-serif, -apple-system, Segoe UI, Roboto, Hiragino Sans, Noto Sans JP, Yu Gothic UI, Meiryo)。コード・frontmatter の生テキスト・`editorFont = "mono"` 設定のときだけ iA Writer Mono S(同梱済み)。外部フォントの読み込みなし。リズムは UI 14px / エディタ 17px
- **トークン**: 上流の `--ui-*` `--editor-*` などの名前は残して値を差し替え、新しい名前は `--sb-*`。生の色コードは `_tokens.scss` とダークのミックスイン以外に書かない
- **色**(WCAG を計測): ライトは背景 #ffffff / パネル #f6f7f8、文字 #1c2128、補助 #5b6572(5.9:1)、アクセント #2f5fb3、リンク #2456b0、危険 #b42318。ダークは背景 #131518 / パネル #191b1f、文字 #e6e9ee、補助 #a3abb6(7.9:1)、アクセント #79a9f2、危険 #ff8a80
- **部品の文法**: 7 種(text, primary, danger, icon, segment, chip, input)× 2 サイズ(32px / タッチ 44px)、フォーカスリング 2px、ホバーは color-mix の重ね、角丸 4/8/12、影 3 段(縁は髪の毛線が担う)。ポップオーバーは `.sb-popover` で共通化(ツリー・ビュー・グラフ)
- **トップバー**はページと同じ色 + 髪の毛線、ドックは一段暗く。モーダルには 24% / 48% の暗幕と影(ぼかしは Pi とスマホに重いので使わない)
- **通知**は画面下中央、Undo 付き。パネル内の注意は行として置き、本文に重ねない
- **グラフ**: ノードに 1px の縁、タグごとに色相、辺の凡例(実線リンク / 点線言及 / 破線類似)、操作部は下隅で現在ノードに重ねない、スマホは下からのシート
- **動き**: 80 / 160 / 240ms、cubic-bezier(.2,.8,.2,1)、フェード + 4px の上昇、拡大や跳ねは無し。`prefers-reduced-motion` で止める
- **密度**は 1 種類(行 36px、タッチ 44px、表の行 34px、エディタ幅 800px)。コンパクト設定は作らない

## 8. 進め方と検証
- 実装は 5 系統(テーマ / サイドバー / DB ビュー / グラフ / Lua の画面)に分け、ファイルを重ねずに並行
- 画面は `scripts/ui-shot.sh` と `scripts/ui-tour.mjs`(コンテナ内の Playwright)で撮り、ライト/ダーク × デスクトップ/スマホの同じ 44 画面を毎回比較する。デモ用のスペースは `examples/demo-space`
- 採点(100 点満点、ベースライン → 実装後): ビジュアルのリード 38 → 78、プロダクトデザイナー 38 → 74(2026-10-03)
